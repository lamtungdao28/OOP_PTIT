# Mock Data

`mock-data.sql` targets MySQL 8.4 and the current Hibernate-generated schema.
It is a manual seed script; application startup does not run it automatically.

| Entity | Fixture count |
| --- | ---: |
| Subject | 10 |
| Semester | 3 |
| CourseClass | 24 |
| Lecturer | 4 |
| User (lecturer dependency) | 4 |
| SemesterHasSubject | 24 |

Rows use `MOCK-` codes or `Mock - ` names. IDs are generated by MySQL, and
relationships resolve IDs from fixture codes and names. Re-running the script
inserts only missing rows; it does not update or delete existing data.

There are 9 active subjects, 1 inactive subject, 8 active classes and 16 inactive
classes. The current semester is `Mock - Hoc ky 1 2026-2027`. Classes have capacities
from 30 to 60. Fixture users are inactive with non-login password markers and
`example.test` addresses; they are not login credentials.

Run from the backend directory against the local Compose container after Hibernate
has created the tables, including `course_classes.semestersid`:

```sh
docker exec -i spring_mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot java_sql' < src/main/resources/db/mock-data.sql
```

Sample API requests:

```http
GET /api/admin/subjects?subject=subjectCode~MOCK-&page=0&size=5
GET /api/admin/semesters?semester=name~Mock&page=0&size=5
GET /api/admin/classes?courseClass=classCode~MOCK-&page=0&size=5&sort=classCode,asc
GET /api/admin/classes?courseClass=classCode~MOCK-&courseClass=status:ACTIVE
```

Use IDs returned by these endpoints when calling `GET /api/admin/classes/{id}`
or filtering classes by `subjectId`, `semesterId`, or `lecturerId`.
